## Goal

Every activity, phase, gate and parallel track in `ROADMAP.md` (v0.2) is owned by a
registered task-tree under `docs/tasks/`, with leaves at the granularity the roadmap
supports today, and an index (`docs/TASK_TREE.md`) a fresh session can resume from
without reading the roadmap end to end.

Two invariants, both directions:

- **No unowned roadmap requirement.** Every G0–G7 exit criterion and every V-track exit
  criterion is a leaf in some tree, or an explicitly recorded `blocked` leaf naming what
  it waits on.
- **No unjustified tree.** Every tree cites the roadmap lane/gate it executes; a tree the
  roadmap does not require is a defect.

## Non-Goals

- Executing any gate's work — each gate tree owns that.
- Re-opening decisions locked by roadmap §15. Alignment and traceability only; a challenge
  is an explicit, argued change recorded in the roadmap's Disposition Log.
- Speculative decomposition of gates that are not yet entered. Later-gate trees carry
  leaves at exit-criterion granularity and are refined at gate entry (per
  `docs/TASK_TREE_README.md`, "discover subtasks").

## Acceptance Criteria

- `docs/TASK_TREE.md` registers every tree with a live frontier row and no dead link.
- One tree per roadmap lane: `G0-CONTRACT` … `G7-RELEASE`, `V1-ASSEMBLY`, `V2-SIM`, plus
  the `SPINE` hygiene lane and this tree.
- Each tree names the roadmap sections/gate it executes; each leaf names its source clause.
- A coverage map shows roadmap gate → tree, with every exit criterion accounted for.
- The derived Knowledge Map lists the trees (regenerated by the pre-commit hook).
- Each completed leaf is committed through `COMMIT.md`.

## Decisions

- `2026-09-29`: tree ids are the roadmap's own lane names (`G0-CONTRACT` … `V2-SIM`) so a
  gate clause and its owning tree are mutually findable; the spine/hygiene lane is `SPINE`
  and the mapping lane is `PLANNING`.
- `2026-09-29`: work-unit ids follow the bootstrap precedent — `STITCHCAD-<AREA>-<NNNN>`,
  with the leaf id named in the subject (`COMMIT.md`).
- `2026-09-29`: later-gate trees are seeded at exit-criterion granularity, not decomposed
  speculatively. Rationale: a leaf written before its gate's evidence exists is a guess, and
  a guess tracked as a commitment is worse than an empty frontier.
- `2026-09-29`: G0 normative specifications live in the mdBook (`docs/book/src/spec/`), not
  in a private `docs/spec/` tree — the director reviews the book, and a spec nobody reviews
  is not a contract. ADR-style decisions stay in `docs/decisions/` (memory layer C), which is
  how roadmap §4.3's `docs/adr/` is realised here; recorded as a decision so the path change
  is deliberate, not silent.
