# Builtin command workflows and native evidence

The immutable core registry declares three current workflows once, through CommandWorkflowId and
CommandWorkflowStep. Commands, classes and complete purpose-permission sets are projected from those
stages and the actual command catalog. Mutation-group permission metadata uses the same purpose rule
as actual core authorization. Discovery reads no model, session, grant, policy or remaining quota.

## Reading the metadata

```rust
use sc_core::command::{CommandAuthority, CommandWorkflowId};

let workflow = CommandWorkflowId::EditMetadata;
assert_eq!(workflow.token(), "edit_metadata");
assert_eq!(workflow.required_authorities(),
           vec![CommandAuthority::Inspect, CommandAuthority::Commit]);
for stage in workflow.steps() {
    let commands = stage.commands();
    let exact_permission = stage.required_authority();
    // Adapters still route actual arguments through freshly authorized bus operations.
}
```

Exact from_token lookup accepts only the published spelling, without whitespace/case aliases or a default.
The inspection workflow needs only Inspect. Its actual query requires no edit capacity or installed
mutation policies. The edit workflow reads Pieces, previews the original three-member metadata group,
commits it once, retrieves its exact accepted replay, then reads the resulting Pieces. The group
contains AssignMaterial, ChangeMeasurement and AddNotch, in that order. The history workflow reads,
commits that same kind of group, reads, Undoes and reads, then Redoes and reads. Undo/Redo retain the
original group's command scope rather than inventing new catalog commands.

Every actual group operation retains its own complete live grant/scope and current revision checks.
Permissions are independent: Commit does not include Inspect, and Inspect does not include Commit.
The registry reports the complete set needed across stages; it neither combines incomplete grants
nor supplies an authenticated decision. Distinct workflow stages are separate operations. Atomicity
belongs to each metadata group or history action, not to the whole multi-operation workflow.

## Native acceptance and remaining scope

The actual native acceptance follows every registered stage through CommandBus using complete real
DesignSources, canonical inputs and the supported garment fixture. It checks the declared metadata
group, exact preview/publication, identity issuance, accepted replay, current Piece reads and complete
snapshot Undo/Redo. A separate grant check verifies that missing Inspect or Commit remains a real
refusal, matching the independently required permission set.

The core registry/book projection is checked by command_workflow_contract. Actual runtime evidence
lives in command_bus::workflow_registry inside sc-measure's design_inputs_contract target. These
checks certify the named native paths. [Combined native acceptance](#combined-native-acceptance)
now covers the current metadata bus/public contracts; full publication probes remain separately owned. They grant no adapter availability or parity, persistent recovery, recipe
reevaluation, geometry, physical/profile realization, allocator/time or release certificate.

Library discovery itself does not install the three required policies, provide finite journal/history
capacity, refill identity reserves, authenticate a session, select a complete grant or guarantee that
a particular request will pass. Those prerequisites and all fresh failures remain at the actual bus.
